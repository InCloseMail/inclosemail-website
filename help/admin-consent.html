Approve InCloseMail for your organization

If your organization lets only administrators approve apps, people see “Need admin approval” when they sign in, and again when they first use some features. One approval covers every permission for everyone in your organization, so nobody is asked again.

Approve for my organization

Sign in as a Global Administrator, Cloud Application Administrator or Application Administrator. Microsoft lists the permissions below and asks you to accept. Afterwards you come back to this page, which says whether it worked.

You can also do it in the Microsoft Entra admin center: Enterprise applications → InCloseMail → Permissions → Grant admin consent (InCloseMail is listed there once anyone in your organization has signed in).

What each permission is for

All of them are delegated: InCloseMail acts only as the person signed in, and only on mail, calendars and contacts that person can already open. It has no access of its own, nothing runs on a server, and no mail leaves their PC except to Microsoft.

InCloseMail asks for all of them except Group.Read.All the first time someone signs in, so nobody is asked again later. Personal Outlook.com accounts get only the ones that apply to them. If your organization approves only some, InCloseMail works with what it has, and a feature whose permission is missing asks for it when it’s used.

To see which permissions an account has, open File → Info → Permissions in InCloseMail. It lists each feature as allowed or not, and Allow asks for a missing one. Copy details copies the list to send to an administrator or to support.

Approving Microsoft 365 Groups

Group.Read.All isn’t part of sign-in, and the Approve for my organization button above doesn’t include it, so approving InCloseMail never approves Groups by itself. It’s asked for only when someone clicks Browse Groups on InCloseMail’s Home tab.

  • To turn Groups on for everyone: sign in to InCloseMail as an administrator, click Browse Groups, tick Consent on behalf of your organization in Microsoft’s window, and accept. Nobody in your organization is asked again.
  • To leave Groups off: don’t approve it. People who click Browse Groups see that it needs an administrator’s approval (or can send you a request, if your organization uses admin consent requests), and the rest of InCloseMail works as usual.

The hidden settings folder

So people’s settings follow them between PCs, InCloseMail keeps them in each person’s own mailbox: a hidden folder named InCloseMail Settings at the top of the mailbox, holding one message whose text is the settings as JSON (options and views, Safe Senders, Quick Steps, signatures, templates and the like). It’s made with the Mail.ReadWrite permission above; nothing is stored anywhere else, and no messages are copied into it. Outlook and Outlook on the web don’t show it; Graph lists it with includeHiddenFolders=true.

Deleting the folder is safe: the next PC to sync writes it again from its own settings. A PC where changes to the mailbox are turned off only reads it. People can turn syncing off on a PC in File → Options → Advanced → Keep my settings the same on every PC. To turn it on or off for everyone, use the Keep users’ settings the same on every PC policy (registry value SyncSettings, 1 or 0, under SOFTWARE\Policies\inclosemail) in InCloseMail’s Group Policy and Intune templates; when it’s switched off, InCloseMail neither reads nor writes the folder.

Script rules

People can set up rules that run a script of theirs (.ps1, .cmd, .bat or .exe) when matching mail arrives, as classic Outlook’s “run a script” rule did. The script runs as the signed-in Windows user, gets the message only as files (never on its command line), and PowerShell runs it with the RemoteSigned execution policy, which your own execution policy overrides. To turn script rules off, use the Don’t run script rules policy (registry value DisableScriptRules, 1) in InCloseMail’s Group Policy and Intune templates.

Removing InCloseMail

In the Entra admin center, Enterprise applications → InCloseMail → Properties → Delete removes it and every approval. Signed-in copies stop working at once.
